## Project Brief

Build a full-stack web application called **"LeafCheck AI"** (or similar) — an AI-powered plant disease detection tool for **Capsicum, Potato, and Tomato** crops, based on the research project "Vision AI for Plant Disease Detection in Capsicum, Potato, and Tomato" by Anshpreet Kaur (Chitkara University).

### Problem it solves
Farmers, especially in rural/semi-urban India, rely on slow manual diagnosis of plant diseases. By the time visual symptoms are noticed, the disease has already spread, leading to crop loss, pesticide misuse, and higher costs. This tool gives farmers instant, accessible, image-based disease detection.

### Core Features (MVP)
1. **Landing page** — explains the problem, the solution, and how it works (upload → AI analyzes → get result). Should feel trustworthy and farmer-friendly, not overly "techy."
2. **Upload/Scan page** — user uploads or takes a photo of a leaf (Capsicum, Potato, or Tomato).
3. **Prediction result page** — shows:
   - Crop type detected
   - Health status: Healthy / Diseased
   - If diseased: specific disease name (e.g., Early Blight, Bacterial Spot, Late Blight)
   - Confidence score (%)
   - Simple recommended next steps (e.g., "Isolate affected plants," "Consult local agri officer," "Reduce watering")
4. **How it works page** — simple explainer: CNN model trained via transfer learning (MobileNetV2/ResNet50) on labeled leaf image datasets, classifies leaf as healthy/diseased + disease type.
5. **About/Research page** — brief summary of the research (abstract, dataset source: Kaggle, model choice, accuracy/loss info) for credibility.
6. **Responsive design** — must work well on mobile since target users are farmers using phones in the field.

### Tech Stack
- **Frontend:** React (Vite) + Tailwind CSS
- **Backend:** Python FastAPI (to serve the ML model) OR Node.js/Express if you want to keep it simpler and mock the prediction initially
- **ML Model:** For MVP, integrate a placeholder/mock prediction function that returns realistic dummy results (crop, disease, confidence). Structure the code so a real trained Keras/TensorFlow model (`.h5` or `.tflite`) can be plugged in later via a `/predict` API endpoint.
- **Image upload:** Support drag-and-drop + camera capture on mobile (`<input type="file" accept="image/*" capture="environment">`)
- **Deployment:** Should run directly on Replit with `npm run dev` / `uvicorn` as appropriate.

### API Contract (for later real-model integration)
```
POST /api/predict
Body: multipart/form-data with "image" file
Response JSON:
{
  "crop": "Tomato",
  "status": "Diseased",
  "disease": "Early Blight",
  "confidence": 0.94,
  "recommendation": "Remove affected leaves, apply copper-based fungicide, avoid overhead watering."
}
```

### Design Direction
- Warm, earthy, trustworthy palette (greens, soil browns, warm neutrals) — NOT a generic dark-mode SaaS look.
- Clear, large, legible typography — many users may be on low-end phones/slow internet.
- Hero section should visually show a leaf being "scanned"/analyzed (icon or illustration is fine, no need for real AI-generated images).
- Use simple icons/illustrations over stock photos for lightweight loading.
- Include a "For Farmers" tone — plain language over technical jargon on all user-facing text; technical details go only on the About/Research page.

### Pages/Routes
- `/` — Landing page
- `/scan` — Upload & analyze
- `/result` — Prediction result (or same page as /scan with state)
- `/how-it-works`
- `/about`

### Nice-to-haves (if time permits)
- Multi-language toggle (English/Hindi) since target users are Indian farmers
- History of past scans (local storage is fine for MVP)
- Downloadable/shareable result card (image or PDF)

### Deliverable
A working, deployed Replit app with the landing page, upload flow, and mock prediction result all functioning end-to-end, ready for a real ML model to be swapped in later.
